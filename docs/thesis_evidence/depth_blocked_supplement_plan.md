## Split Strategy

### depth_heldout_simple

Use sorted sonic depth and contiguous non-overlapping ranges. Add a guard gap between train/validation/test to reduce adjacent-depth leakage. Exact sample counts must be generated by the split manifest script rather than guessed in the thesis.

Recommended first run:

| Split | Depth range ft | Role |
| --- | --- | --- |
| train | `[2732.44, 3707.00)` | main training interval |
| guard | `[3707.00, 3712.00)` | excluded buffer |
| validation | `[3712.00, 3916.00)` | early stopping and model selection |
| guard | `[3916.00, 3921.00)` | excluded buffer |
| test | `[3921.00, 4131.75]` | final heldout reporting |

Rationale: this preserves the single-well depth order, avoids random mixing of adjacent samples, and keeps a simple train/val/test layout that is easy to explain in the thesis. It is a stronger claim than the old random split but still only evaluates heldout depth intervals within the same well.

Required manifest fields:

- `sample_index`
- `record_index`
- `sonic_depth`
- `split`
- `split_reason`
- `source_tfrecord`
- `source_processed_waveforms_pkl`
- `source_idx_pkl`
- `guard_gap_ft`
- `created_from_branch_or_commit`

### depth_blocked_kfold_optional

If the simple split is too dependent on one bottom interval, run contiguous block folds. This is optional and should only be added after EXP-008 simple heldout has completed.

Equal-width block proposal from the observed depth range:

| Block | Depth range ft |
| --- | --- |
| B0 | `[2732.44, 3012.30)` |
| B1 | `[3012.30, 3292.16)` |
| B2 | `[3292.16, 3572.02)` |
| B3 | `[3572.02, 3851.88)` |
| B4 | `[3851.88, 4131.75]` |

For each fold, hold out one block as test, use one non-test block as validation, and train on the remaining blocks after removing a guard gap around the heldout block. Do not stratify by random sample after this, because that reintroduces depth leakage.

## Minimal Execution Design

The safest minimal design is to split existing TFRecord records into split-specific TFRecords by depth, instead of regenerating raw preprocessing or modifying the old Windows results.

1. Create a split manifest from `processed_waveforms.pkl`, `ground_truth_db_array_03.h5`, and existing `.idx.pkl` where available.
2. Copy serialized TFRecord examples into `train.tfrecord`, `val.tfrecord`, and `test.tfrecord` according to the manifest.
3. Train using `train.tfrecord` and `val.tfrecord`.
4. Evaluate only on `test.tfrecord`.
5. Save metrics, split manifest, train/val/test depth ranges, config, and leakage audit into a new safe output directory.

No old result or raw data file should be overwritten.
